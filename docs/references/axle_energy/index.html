Axle Energy

Instructions on how to use Axle Energy grid event schedules in Home Assistant.

The Axle Energy integration shows the grid event schedule for your Axle Energy account. You can use the event direction and start and end times in your automations to prepare for an import or export event.

Prerequisites

You need an Axle account with access to a Home Assistant authentication token. Axle provides this token in Events Only mode.

To create a token:

  1. Sign in to your Axle account and open Account Settings.
  2. Open the Home Assistant section.
  3. Select Generate Token.
  4. Copy the token for use during setup.

If the Home Assistant section is unavailable, check your account mode and refer to Axle's Home Assistant setup instructions.

Configuration

To add the Axle Energy service to your Home Assistant instance, use this My button:

Config flow start

Manual configuration steps

If the above My button doesn't work, you can also perform the following steps manually:

  • Browse to your Home Assistant instance.

  • Go to Settings > Devices & services.

  • In the bottom right corner, select the Config flow start button.

  • From the list, select Axle Energy.

  • Follow the instructions on screen to complete the setup.


API key:
  description: "Enter the Home Assistant token generated in your Axle account. Paste the token on its own, without a `Bearer ` prefix."

Reconfiguration

You can recheck your existing Axle Energy token or replace it at any time:

  1. Go to Settings > Devices & services, select Axle Energy, and open the three-dot menu for the entry you want to update. Select Reconfigure.
  2. If you are replacing the token, open the Home Assistant section of your Axle account. If Generate Token is available, select it, then copy the token.
  3. The API key field is prefilled with the current token. Leave it unchanged to recheck the token, or replace it with the token you copied. Do not include the Bearer prefix.
  4. Select Submit.

Home Assistant validates the token before updating the entry. If the token is invalid or is already used by another entry, an error is shown and the form stays open so you can enter a different token. Your saved token is unchanged. A successful update preserves the entry's sensors and entity IDs, so your automations can continue using them. Each configured feed needs its own token.

Supported functionality

Each configured feed creates one service device with the following entities:

  • Participation shows whether your Axle account is Opted in or Opted out. The status is available even when no event is scheduled.
  • Event in progress is on from the start of a participating import or export event until its end. It is off before and after the event, when no event is scheduled, or when your account is opted out.
  • Event type shows whether the published event requests import from or export to the grid.
  • Event start shows when the event starts.
  • Event end shows when the event ends.
  • Events shows the current or next announced timed event. Its summary is Import or Export. The calendar is empty when there is no known event, including when you have opted out.

You see event timestamps in your configured time zone. You can use the timestamp sensors with a time trigger in your own automations. The Calendar integration documentation shows how to use start and end triggers, including offsets.

Axle Energy automation examples

Use the event timestamps to schedule notifications from the latest event information received from Axle. Create an automation in Settings > Automations & scenes with the trigger, condition, and action below.

Tip

You don't need to edit YAML to use these examples. Copy a YAML snippet from this page, open the visual automation editor in Home Assistant, and press Ctrl+V (or Cmd+V on Mac). Home Assistant automatically converts the pasted YAML into the visual editor format, whether it's a full automation, a single trigger, a condition, or an action.

Automation: Notify when an export event starts

This example creates a notification in Home Assistant when the scheduled export event starts.

  • Trigger: Time, using the Axle Energy Event start sensor
  • Condition: State, with the Axle Energy Event type sensor set to export
  • Action: Persistent Notification: Create persistent notification
    • Message: Your Axle export event is starting.

YAML example for an export event notification

Replace the entity IDs if you have renamed your Axle sensors.

Example

automation: | alias: "Notify when an Axle export event starts" triggers: - trigger: time at: sensor.axle_energy_event_start conditions: - condition: state entity_id: sensor.axle_energy_event_type state: "export" actions: - action: persistent_notification.create data: message: "Your Axle export event is starting."

Automation: Notify when an event ends

This example creates a notification at the scheduled end of an import or export event.

  • Trigger: Time, using the Axle Energy Event end sensor
  • Action: Persistent Notification: Create persistent notification
    • Message: Your Axle event has reached its scheduled end.

YAML example for an event end notification

Replace the entity ID if you have renamed your Axle sensor.

Example

automation: | alias: "Notify when an Axle event ends" triggers: - trigger: time at: sensor.axle_energy_event_end actions: - action: persistent_notification.create data: message: "Your Axle event has reached its scheduled end."

Automation: Notify one hour before an export event

This example creates a persistent notification one hour before a scheduled Axle export event starts.

  • Trigger: Time, using the Axle Energy Event start sensor
  • Condition: State, with the Axle Energy Event type sensor set to export
  • Action: Persistent Notification: Create persistent notification
    • Message: Your Axle export event starts in one hour.

To set the reminder in the UI, select Value of a date/time helper or timestamp-class sensor in the Time trigger, choose your Event start sensor, and enter -01:00:00 in Offset. To send the reminder two hours before the event, change the offset to -02:00:00 and update the automation alias and notification message to say two hours.

YAML example for an export event reminder

Replace the entity IDs if you have renamed your Axle sensors.

Example

automation: | alias: "Notify one hour before an Axle export event" triggers: - trigger: time at: entity_id: sensor.axle_energy_event_start offset: "-01:00:00" conditions: - condition: state entity_id: sensor.axle_energy_event_type state: "export" actions: - action: persistent_notification.create data: message: "Your Axle export event starts in one hour."

Template helper examples

You can create optional Template helpers from the Axle Energy timestamp sensors. These helpers are separate from the entities created by the integration.

Event later today

Create an optional, user-created Template helper to show whether the next Axle Energy event starts later today. The helper is separate from the Axle Energy entities. It shows Off when there is no event, the timestamp is invalid, the event is not today, or its start time has passed. It shows Unavailable when the source sensor is unavailable.

Create an event later today helper

  1. Go to Settings > Devices & services > Helpers and select Create helper.
  2. Select Template, then Binary sensor.
  3. Enter Axle Energy event later today as the Name.
  4. Paste this into State. Replace the entity ID if you renamed your Axle sensor.

Example

template: | {% set raw = states('sensor.axle_energy_event_start') %} {% set start = as_timestamp(raw, none) %} {% set current = as_timestamp(now()) %} {% set local_now = as_local(as_datetime(current)) %} {% if raw == 'unknown' %} {{ false }} {% elif start is not none %} {% set event_date = as_local(as_datetime(start)).date() %} {{ event_date == local_now.date() and start > current }} {% else %} {{ false }} {% endif %}

  1. Expand Additional options and paste this into Availability, using the same entity ID.

Example

template: | {{ not is_state('sensor.axle_energy_event_start', 'unavailable') }}

  1. Select Submit. You can then add the helper to your dashboard.

The helper updates when its source sensor changes and at the start of each minute. It uses the event timestamp to check whether the start time is still in the future and the local calendar date to determine whether the event is today. An invalid timestamp is handled as Off instead of causing a template error.

Minutes until an event starts

For a numeric countdown, you can create an optional Template helper from the existing Event start and Event end sensors. This helper is separate from the entities created by the Axle Energy integration.

It shows the minutes until the event starts, rounded up to the next whole minute. It shows 0 while the event is in progress, Unknown when there is no event or the event has ended, and Unavailable when either source sensor is unavailable. The helper updates when either source changes and at the start of each minute, without requesting data from Axle. For an automation at an exact event time, use the timestamp sensors with a time trigger.

Create a minutes until event start helper

  1. Go to Settings > Devices & services > Helpers and select Create helper.
  2. Select Template, then Sensor.
  3. Enter Axle Energy minutes until event start as the Name and min as the Unit of measurement. Leave Device class and State class empty.
  4. Paste the following into State. Replace the entity IDs if you have renamed your Axle sensors.

Example

template: | {% set start = as_timestamp(states('sensor.axle_energy_event_start'), none) %} {% set end = as_timestamp(states('sensor.axle_energy_event_end'), none) %} {% set current = as_timestamp(now()) %} {% if start is not none and end is not none and end > current %} {{ [0, ((start - current) / 60) | round(0, 'ceil') | int] | max }} {% else %} {{ none }} {% endif %}

  1. Expand Additional options and paste the following into Availability, using the same entity IDs.

Example

template: | {{ not is_state('sensor.axle_energy_event_start', 'unavailable') and not is_state('sensor.axle_energy_event_end', 'unavailable') }}

  1. Select Submit. You can then add the helper to your dashboard.

Minutes remaining in an event

To see how much time is left in an active event, create an optional Template helper from the existing Event start and Event end sensors. This helper is separate from the entities created by the Axle Energy integration.

It shows the minutes remaining, rounded up to the next whole minute, while the event is in progress. It shows 0 before the event starts or after it ends, Unknown when either timestamp is missing or invalid, and Unavailable when either source sensor is unavailable. The helper updates when either source changes and at the start of each minute, without requesting data from Axle. For an automation at an exact event time, use the timestamp sensors with a time trigger.

Create a minutes remaining helper

  1. Go to Settings > Devices & services > Helpers and select Create helper.
  2. Select Template, then Sensor.
  3. Enter Axle Energy minutes remaining as the Name and min as the Unit of measurement. Leave Device class and State class empty.
  4. Paste the following into State. Replace the entity IDs if you have renamed your Axle sensors.

Example

template: | {% set start = as_timestamp(states('sensor.axle_energy_event_start'), none) %} {% set end = as_timestamp(states('sensor.axle_energy_event_end'), none) %} {% set current = as_timestamp(now()) %} {% if start is not none and end is not none and end > start %} {% if start <= current < end %} {{ ((end - current) / 60) | round(0, 'ceil') | int }} {% else %} {{ 0 }} {% endif %} {% else %} {{ none }} {% endif %}

  1. Expand Additional options and paste the following into Availability, using the same entity IDs.

Example

Data updates

The integration polling polls Axle every 10 minutes. All entities use the same update. Changes to the published schedule and Participation status appear after the next successful update. If Axle does not provide your account's participation status, Participation shows an unknown state.

Event in progress changes at the scheduled start and end times without waiting for the next update or making another request to Axle. It uses the latest schedule received, so a changed or canceled event is reflected after the next successful update.

When Axle returns an empty schedule or your account is opted out, Event in progress is off and the three event detail sensors show an unknown state. If a request fails because of a temporary connection or service error, all entities become unavailable and recover after a successful update. Authentication failures stop polling; follow the steps in Authentication fails to replace the token.

Known limitations

  • Each entry uses its own Axle API key. You can add another feed with a different key.
  • The integration reads your account's participation status and event schedule. It is read-only and does not control your battery or inverter, or change your Axle participation mode.
  • The Events calendar uses the current or next announced event and does not retain a history of previous events.
  • Countdown entities are not provided.
  • The event information depends on Axle's cloud service and may change between updates.

Troubleshooting

Authentication fails

Check that you copied the full token from the Home Assistant section of your Axle account. Enter only the token in API key, without a Bearer prefix.

If Axle rejects the token for an existing feed, Home Assistant displays a notification asking you to authenticate again. Select Reconfigure on the notification. The authentication flow opens with a blank API key field. Before entering a token, open the Home Assistant section of your Axle account. If Generate Token is available, select it, then copy the token. Enter a valid token without a Bearer prefix, then select Submit.

If Axle still rejects the token from your account, contact Axle support. You can also contact support for guidance on revoking an existing token.

The sensors are unavailable

Check your internet connection and whether you can access your Axle account. The integration retries connection failures automatically. If authentication fails, follow the token replacement steps above. If the problem continues, check Settings > System > Logs for an Axle error.

The sensors show an unknown state

An unknown state on Participation means the last successful Axle response did not include the opted_out flag. It does not indicate whether an event is scheduled. An empty schedule is valid: Event in progress is off, and Event type, Event start, and Event end are unknown.

Download diagnostics

If you report a problem, download diagnostics from the Axle Energy integration. The file contains the latest saved event data, the reported opt-out flag, and whether the last update succeeded. Your API key is not included. Downloading diagnostics does not request another update from Axle. Review the file before sharing it.

Removing the integration

To remove an integration instance from Home Assistant

  1. Go to Settings > Devices & services and select the integration card.
  2. Next to the entry you want to remove, select the three dots menu. Then, select Delete.
    • Depending on the integration, the entries are listed under one of the following headings:
      • Devices
      • Hubs
      • Services
      • Integration entries
  3. To confirm, select Delete.
    • Home Assistant also deletes the devices and entities of the entry.
  4. If Home Assistant asks you to restart, restart Home Assistant.
  5. If Home Assistant asks whether to also delete the application credentials, select Remove or Keep.
    • If you keep them, Home Assistant uses them automatically when you add the integration again.
    • To delete them later, refer to Deleting application credentials.

Removing the integration does not close your Axle account or change your participation mode.

### The sensors are unavailable

Check your internet connection and whether you can access your Axle account. The integration retries connection failures automatically. If authentication fails, follow the token replacement steps above. If the problem continues, check {% my logs title="**Settings** > **System** > **Logs**" %} for an Axle error.

### The sensors show an unknown state

An unknown state on **Participation** means the last successful Axle response did not include the `opted_out` flag. It does not indicate whether an event is scheduled. An empty schedule is valid: **Event in progress** is off, and **Event type**, **Event start**, and **Event end** are unknown.

### Download diagnostics

If you report a problem, [download diagnostics](/integrations/diagnostics/) from the Axle Energy integration. The file contains the latest saved event data, the reported opt-out flag, and whether the last update succeeded. Your API key is not included. Downloading diagnostics does not request another update from Axle. Review the file before sharing it.

## Removing the integration

{% include integrations/remove_device_service.md %}

Removing the integration does not close your Axle account or change your participation mode.
