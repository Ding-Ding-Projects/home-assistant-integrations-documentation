LLM

Provides the AI tools that conversation agents and AI apps use to read information, control entities, and manage Home Assistant.

The LLM integration provides the AI tools in Home Assistant. An AI tool is a function that conversation agents and AI apps can use to read information, control entities, or manage Home Assistant. For example, with AI tools, a conversation agent can tell you the temperature in the living room, turn on your lights, or reload an integration that failed to set up.

The AI tools are grouped into sets. You choose which sets each conversation agent can use, in its AI tools option. AI apps outside Home Assistant can use the same sets through the Model Context Protocol integration.

The LLM integration is an internal system integration. It loads as part of the default configuration. Every AI integration that adds a conversation agent loads it too. You can't add or remove it, and it has no options.

Sets of AI tools

Each set contains related AI tools. Home Assistant has two built-in sets:

  • Device control: Reads and controls the entities you expose to voice assistants. For example, it can check the bedroom temperature or turn off the kitchen light. Any user can use it.
  • Home Assistant: Looks into and manages Home Assistant itself. For example, it can read the logs, look up past sensor values, or reload an integration that failed to set up. It can reach all of Home Assistant, not only exposed entities. Only administrators can use it.

On this page, the tools in the Home Assistant set are called the Home Assistant AI tools.

Integrations can add more sets. For example, KNX adds a KNX set, and the Model Context Protocol Client adds a set for each server that you connect.

You choose the sets in the AI tools option of each conversation agent. For example, Anthropic, Google Gemini, Ollama, and OpenAI have this option. A new conversation agent starts with Device control only. In Ollama, it starts with no sets.

Important

Risk of unintended device actions

The Home Assistant set of AI tools can control every entity and change Home Assistant itself. It doesn't ask you before it acts. It also isn't limited to the entities that you expose to voice assistants. If the conversation agent misunderstands a request, it can turn off devices or change settings that you didn't intend to change.

To avoid this:

  • Only select the Home Assistant set for a conversation agent that you use to manage Home Assistant.
  • For everyday voice control, use a separate assistant whose conversation agent only uses Device control. For the steps, refer to Setting up a separate assistant for the Home Assistant AI tools.

What the Home Assistant AI tools can reach

The Home Assistant AI tools can read the state of every entity, the status of your integrations, your logs, and the history of your sensors. For the full list, refer to List of Home Assistant AI tools.

Most of the Home Assistant AI tools only read. Two tools can change things:

  • Call action can perform any action in Home Assistant, on any entity, device, or area. This includes entities that you didn't expose. For example, it can turn off a light, run a script, or restart Home Assistant.
  • Reload config entry can reload an integration.

Who can use the Home Assistant AI tools

Only administrators can use the Home Assistant AI tools. Home Assistant checks the user account that each request comes from. When you talk to a conversation agent in Assist in Home Assistant or in the Home Assistant Companion app, the request comes from the user account that is signed in.

A voice satellite isn't signed in to a user account. For example, Home Assistant Voice Preview Edition is a voice satellite. Its requests don't belong to any user. If its conversation agent has the Home Assistant set selected, every request from the voice satellite fails. This also stops Device control on that conversation agent. This means the voice satellite can't turn on a light either. Requests from users who aren't administrators fail the same way.

Adding the Home Assistant AI tools to your conversation agent

Use this procedure if only administrators use your conversation agent. Afterwards, you can ask it why an integration isn't working, or which errors are in the logs. The conversation agent then no longer works for voice satellites or for users who aren't administrators. For details, refer to Who can use the Home Assistant AI tools.

Prerequisites:

  • An administrator account in Home Assistant.
  • A conversation agent from an AI integration. For example, OpenAI adds conversation agents.

To add the Home Assistant AI tools to your conversation agent:

  1. Go to Settings > Devices & services, and select your AI integration.
    • For example, select OpenAI.
  2. In the row of the conversation agent, select Reconfigure conversation agent .
    • The right row shows Conversation agent under the name. For example, OpenAI calls it OpenAI Conversation.
    • Don't use the rows below it. They show its devices.
    • Some integrations call this button Configure.
  3. Under AI tools, select Home Assistant.
    • To keep controlling your devices, leave Device control selected.
  4. Select Submit. If the dialog shows more options, select Submit again.
    • Result: The conversation agent can use the Home Assistant AI tools the next time you talk to it.

Setting up a separate assistant for the Home Assistant AI tools

Use this procedure if voice satellites or users who aren't administrators use your assistant. Your current assistant stays as it is for them. You get a second assistant that you can ask why an integration isn't working. For details, refer to Who can use the Home Assistant AI tools.

Prerequisites:

  • An administrator account in Home Assistant.
  • An AI integration that adds conversation agents. For example, OpenAI adds them.

To set up a separate assistant for the Home Assistant AI tools:

  1. Go to Settings > Devices & services, and select your AI integration.
    • For example, select OpenAI.
  2. Select Add conversation agent.
  3. Under Name, enter a name for the new conversation agent.
    • For example, enter Home Assistant helper.
  4. Under AI tools, select Home Assistant.
    • To also control your devices with it, leave Device control selected.
  5. Select Submit. If the dialog shows more options, select Submit again.
  6. Go to Settings > Voice assistants, and select Add assistant.
  7. Enter a name for the assistant. Under Conversation agent, select the conversation agent that you just added.
  8. Select Create.
  9. To use the new assistant, open the Assist dialog. At the top, select the name of the current assistant, and then select the new assistant.
    • Result: The new assistant can use the Home Assistant AI tools in the Assist dialog of Home Assistant and of the Home Assistant Companion app. This works when you're signed in with an administrator account.

Supported functionality

List of Home Assistant AI tools

You don't call these tools yourself. When you ask the conversation agent something, it decides which tools to call. You can't select single tools. You give the conversation agent the entire set, as described in Adding the Home Assistant AI tools to your conversation agent.

The Home Assistant set of AI tools contains the following tools. Each entry starts with the title of the tool, followed by its ID. The Assist dialog shows the ID under Show details. Many tools do something that you can also do yourself in the UI, without a conversation agent. Where you can, the entry says how. For example, you can check what the conversation agent tells you.

  • Render template (homeassistant__render_template): Renders a template and returns the result. Templates can read the state and attributes of all entities. Only reads.
    • To do this yourself: Use the Template tab, under Settings > Tools > Template.
  • Search actions (homeassistant__search_actions): Finds the actions that Home Assistant can perform, with their targets and fields. Only reads.
    • To do this yourself: Use the Actions tab, under Settings > Tools > Actions.
  • Call action (homeassistant__call_action): Performs an action, and returns its response if it has one. Changes things.
    • To do this yourself: Use the Actions tab, under Settings > Tools > Actions.
    • To see which actions the conversation agent performed: Go to Settings > Tools > Action history.
  • Get config entries (config__get_config_entries): Lists the integrations and helpers that are set up, with their status, such as loaded or failed to set up, and the reason for an error. It can filter by integration and by status. Only reads.
    • To do this yourself: Go to Settings > Devices & services.
  • Reload config entry (config__reload_config_entry): Reloads an integration that is set up. For example, it helps after a temporary connection error. Changes things.
    • To do this yourself: On the integration page, under Settings > Devices & services, select Menu > Reload on the integration entry.
  • Search available integrations (config__search_integrations): Searches the integrations and helpers that you can set up from the UI, including ones that you haven't added yet. Only reads.
    • To do this yourself: Select Add integration, under Settings > Devices & services.
  • Search Home Assistant (search__search): Finds entities, devices, areas, labels, automations, scripts, and scenes by name. Only reads.
    • To do this yourself: Use the quick search.
  • Get system info (system_health__get_system_info): Returns the installation type, the CPU architecture, the time zone, and the versions of Home Assistant Core, the frontend, Python, the operating system, and the Supervisor. For example, you can use it to fill in a bug report. Only reads.
    • To do this yourself: Under Settings > System > Repairs, select Menu > System information.
  • Get history (history__get_history): Returns statistics of entities, not their individual state changes. For example, it can return the mean, minimum, and maximum temperature per 5 minutes or per hour. It only works for entities with statistics, such as sensors with a state class. Only reads.
    • To do this yourself: Use the History panel.
  • Get system log entries (system_log__get_entries): Returns recent errors and warnings from the system log. It doesn't include info or debug messages. It can filter by level and by integration. Only reads.
    • To do this yourself: Go to Settings > System > Logs.
  • Get logs (system_log__get_logs or hassio__get_logs): Reads the full logs in a time window. This includes info and debug messages, if Home Assistant logs them. Values that look like credentials are masked. Only reads.
    • On Home Assistant Operating System and Home Assistant Supervised installations, the ID is hassio__get_logs. It also reads the logs of the Supervisor, the operating system, the DNS, audio, and multicast plugins, and your apps.
    • On Home Assistant Container installations, and on other installations without the Supervisor, the ID is system_log__get_logs. It only reads the Home Assistant log, and it needs the log file.
    • To do this yourself: Under Settings > System > Logs, select Menu > Show raw logs.
  • Get date and time (llm__GetDateTime): Returns the current date and time. Both built-in sets of AI tools, Device control and Home Assistant, have this tool. Only reads.

Known limitations

Access to AI tools

  • Only administrators can use the Home Assistant AI tools. Requests without an administrator account fail. For example, requests from a voice satellite fail, and so do requests from users who aren't administrators. This also stops Device control on that conversation agent, because the agent can't prepare any of its sets of AI tools.
  • The Home Assistant Cloud conversation agent of Home Assistant Cloud can't use the Home Assistant AI tools. It always uses Device control.

Entity history

  • Get history returns statistics, not individual state changes. Entities without statistics have no history for this tool. For example, a switch has no statistics, and neither does a sensor without a state class. For how statistics work, refer to Long-term statistics.

Logs and credentials

  • In Home Assistant Container installations, and in other installations without the Supervisor, Get logs needs the Home Assistant log file. If Home Assistant doesn't write a log file, this tool isn't available. For example, the HA_DISABLE_LOG_FILE environment variable turns off the log file.
  • Get logs masks values that look like credentials, such as tokens, passwords, and API keys. It can't recognize every credential, so other secrets in your logs can still reach the AI provider.

Troubleshooting

The conversation agent answers “Error preparing LLM API”

Symptom: "Error preparing LLM API"

When you talk to a conversation agent, it doesn't do what you asked. Instead, it answers "Error preparing LLM API".

Description

The conversation agent couldn't prepare its sets of AI tools. This happens in the following situations:

  • The conversation agent has the Home Assistant AI tools, and the request doesn't come from an administrator. For example, it comes from a voice satellite, or from a user who isn't an administrator. In this case, Device control doesn't work on this conversation agent either.
  • A set of AI tools that the conversation agent uses no longer exists. For example, you removed the integration that added it.

Resolution

The Home Assistant AI tools only work for administrators. You can't make them available to other users or to voice satellites. If a voice satellite or a user who isn't an administrator uses this conversation agent, remove the Home Assistant AI tools from it:

  1. Go to Settings > Devices & services, and select your AI integration.
  2. In the row of the conversation agent, select Reconfigure conversation agent .
    • In some integrations, this button is called Configure.
  3. Under AI tools, clear Home Assistant.
    • To keep controlling your devices with this conversation agent, make sure Device control is selected.
  4. Select Submit. If the dialog shows more options, select Submit again.
    • Result: The conversation agent controls your devices again, for everyone who uses it.

To keep using the Home Assistant AI tools yourself, set up a separate assistant for them. For the steps, refer to Setting up a separate assistant for the Home Assistant AI tools.

If you removed the integration that added a set of AI tools, open the settings of the conversation agent, as described in steps 1 and 2 above. Then, select Submit. If the dialog shows more options, select Submit again. The settings only show the sets of AI tools that still exist, so saving them removes the missing set.

Get history: “No statistics are recorded for this entity”

Symptom: The conversation agent can't tell you the past values of an entity

You ask the conversation agent about the past values of an entity, and it can't answer. Under Show details in the Assist dialog, the result of history__get_history says "No statistics are recorded for this entity."

Description

Get history only reads statistics, not individual state changes. Home Assistant only keeps statistics for entities that measure something over time, such as a temperature sensor or an energy meter. Other entities have no statistics. For example, a switch has none. For how statistics work, refer to Long-term statistics.

Resolution

  • To see the past states of the entity yourself, use the History panel.
  • If the entity is a sensor that should have statistics, check for an issue under Settings > Tools > Statistics. For how to fix it, refer to Fixing a statistics issue.

### Symptom: The conversation agent can't tell you the past values of an entity

You ask the {% term "conversation agent" %} about the past values of an {% term entity %}, and it can't answer. Under **Show details** in the {% term Assist %} dialog, the result of `history__get_history` says "No statistics are recorded for this entity."

#### Description

**Get history** only reads statistics, not individual state changes. Home Assistant only keeps statistics for entities that measure something over time, such as a temperature sensor or an energy meter. Other entities have no statistics. For example, a switch has none. For how statistics work, refer to [Long-term statistics](/docs/configuration/long-term-statistics/).

#### Resolution

- To see the past states of the entity yourself, use the {% my history title="**History**" %} panel.
- If the entity is a sensor that should have statistics, check for an issue under {% my developer_statistics title="**Settings** > **Tools** > **Statistics**" %}. For how to fix it, refer to [Fixing a statistics issue](/docs/tools/dev-tools/#fixing-a-statistics-issue).
